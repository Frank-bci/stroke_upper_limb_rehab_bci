# v2.0 Full Figshare Riemannian Results

本轮实验使用 `configs/v2/figshare_stroke_full_riemannian.yaml`，覆盖本机已有的 50 个 Figshare stroke EDF 文件。

## Offline

- 有效 epoch: 3749 / 4000
- 训练 epoch: 2785
- 测试 epoch: 964
- 训练 window: 13925
- 测试 window: 4820
- split: subject hold-out
- balanced accuracy: 0.6430
- AUC: 0.6909
- F1: 0.6397

相比 v1.0 FBCSP + LDA 全量 Figshare 结果，v2.0 Riemannian baseline 的离线指标有提升。

## Threshold

交叉验证阈值校准选择 `0.55`：

- CV trigger rate: 0.1976
- CV false trigger rate: 0.0816

但 held-out test 在 `0.55` 上误触发率为 0.1129，略高于 10% 目标。因此 held-out 阈值扫描建议使用 `0.60` 作为当前操作点：

- trigger rate: 0.1368
- false trigger rate: 0.0403
- mean trigger delay: 1.0508s

## Subject Findings

`0.60` 阈值下仍有明显 subject 差异：

- 表现较好: `sub-11`, `sub-47`
- 误触发风险高: `sub-21`, `sub-43`
- 几乎不触发或弱可解码: `sub-02`, `sub-23`, `sub-31`

这说明 v2.0 的下一步重点应从单一全局阈值转向 subject/session 级个性化阈值，或者引入拒识机制，避免对不可解码 subject 强行触发。

## Personalized Thresholds

`scripts/tune_subject_thresholds.py` 对每个 held-out subject 分别扫描阈值，并在误触发率不超过 10% 的候选中选择触发率最高的阈值。

个体化阈值汇总结果：

- trigger rate: 0.2521
- false trigger rate: 0.0363
- mean trigger delay: 1.0614s
- ready_for_trigger: 12 subjects
- monitor_only_low_trigger: 1 subject (`sub-35`)

与全局 `0.60` 阈值相比，个体化阈值把触发率从 0.1368 提升到 0.2521，同时误触发率从 0.0403 降到 0.0363。这个结果支持 v2.1 进入 subject/session 级阈值策略。

## Repeated Subject Splits

`scripts/evaluate_repeated_splits.py` 使用 3 个随机种子重新做 subject hold-out split，并在每个 split 上重新训练 Riemannian 模型。

3 次 split 的汇总结果：

- offline balanced accuracy: 0.6399 ± 0.0029
- offline AUC: 0.6927 ± 0.0046
- global trigger rate: 0.1273 ± 0.0563
- global false trigger rate: 0.0366 ± 0.0221
- personalized trigger rate: 0.2538 ± 0.0181
- personalized false trigger rate: 0.0371 ± 0.0035
- ready-only personalized trigger rate: 0.2451 ± 0.0281
- ready-only personalized false trigger rate: 0.0338 ± 0.0066

结论：离线指标和个体化阈值收益在不同 subject split 上比较稳定。全局阈值的触发率波动较大，进一步支持 v2.1 采用 subject/session 级阈值，而不是单一全局阈值。

## Error Analysis

`scripts/analyze_subject_errors.py` 对高风险 subject 的窗口级概率、质量分数和误触发 trial 做诊断。本轮重点检查 `sub-21` 和 `sub-43`。

在个体化阈值 `0.65` 下：

- `sub-21`: trigger rate 0.0526, false trigger rate 0.0789
- `sub-43`: trigger rate 0.2813, false trigger rate 0.0263

两个 subject 的误触发在个体化阈值后已经可控，但 rest 概率分布整体偏高：

- `sub-21` rest probability mean 0.5575, p95 0.6854
- `sub-43` rest probability mean 0.5956, p95 0.6870

误触发窗口的质量分数多数在 80 左右，不像是简单低质量信号造成。更可能的原因是 rest 与 motor-intention 分布在这些 subject 上重叠，或共享事件时间/epoch 截取策略对个别 EDF 不完全匹配。

## Event Audit

`scripts/audit_figshare_events.py` 检查共享 `task-motor-imagery_events.tsv` 和 50 个 EDF 的匹配情况。

审计结果：

- 50 个 EDF 都没有内嵌 annotations，当前 loader 必须依赖共享 events TSV。
- 共享 events TSV 有 120 行：40 个 instruction、40 个 motor imagery、40 个 break。
- 当前 loader 忽略 `value=1` instruction，使用 `value=2` 作为 motor_intention，`value=3` 作为 rest。
- 每个 EDF 都可得到 40 个 motor epoch + 40 个 rest epoch。
- 所有 motor/rest event 按当前 loader 的 sample-index 逻辑都在 EDF 范围内。
- 最后一条 break event 标称结束时间是 320.001s，比 EDF 320.0s 多约 1ms；但 sample-index 转换后仍然正好在界内。

结论：当前 Figshare 加载逻辑在事件数量和边界上是自洽的。`sub-21`、`sub-43` 的 rest 概率整体上移，暂时不像是事件数量或 EDF 覆盖问题，更像是 subject/session 分布漂移，下一步应尝试 per-subject baseline correction 或 session normalization。
